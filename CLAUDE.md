## What this is

Frontend for **Capstone Defense Scheduler** at FPT University's Software Engineering department — replaces manual Excel-based scheduling of capstone evaluation rounds (Review 1/2, Defense 1.1, Defense 1.2/2) with a system that collects lecturer availability, auto-schedules under hard/soft constraints, publishes results, and tracks changes via audit log. Four roles: Admin, Manager, Lecturer, Student (see `PRODUCT.md` for role details and design principles — Vietnamese-language UI, mobile-first for availability/schedule viewing, orange-on-white brand).

## Commands

```bash
npm run dev              # start dev server
npm run build             # production build
npm run lint               # eslint
npx tsc --noEmit          # type-check (no dedicated script; used directly in CI)
npm test                    # vitest run (all tests)
npx vitest run <path>       # run a single test file
npm run typegen -- <path-to-be-openapi.json>       # regenerate lib/api/generated/* from a local BE openapi.json checkout
npm run typegen:check -- <path-to-be-openapi.json> # regenerate + verify committed generated files match BE contract exactly (used in CI)
```

CI (`.github/workflows/frontend.yml`) runs on push/PR touching `app/`, `components/`, `hooks/`, `lib/`, `scripts/`: lint → typecheck → `npm test` → `typegen:check` against the sibling `f-caps-schedule-be` repo's `apps/api/openapi.json` (same branch name, falling back to `main`).

## Architecture

### This is not the Next.js you know

Next.js 16 with breaking changes from training-data knowledge — notably **middleware was renamed to Proxy** (`proxy.ts` at repo root, not `middleware.ts`). Before writing routing/proxy/server code, read the relevant guide under `node_modules/next/dist/docs/`. See `AGENTS.md`.

### Auth model (see `docs/auth.md`)

- The real session is a `HttpOnly` cookie set by the backend — the FE never reads or holds it directly.
- FE sets its own readable cookie, `session_role` (`SESSION_ROLE_COOKIE` in `lib/constants/auth.ts`), purely for **routing UX** after login — it is not a security boundary. Every request is still authenticated server-side by the real session cookie.
- `proxy.ts` reads `session_role` to redirect unauthenticated users to `/login` and to keep each role inside its own area (`/admin`, `/manager`, `/lecturer`, `/student`), plus the shared `/my-schedule` route available to any logged-in role.
- A CSRF token is read from the `scheduler_csrf` cookie and attached as `X-CSRF-Token` on mutating requests (`lib/api/core.ts`).
- A 401 from any *non*-auth endpoint fires a global `auth:unauthorized` window event (consumed by `useAuthSyncAcrossTabs`) to trigger logout; 401s from `/api/v1/auth/*` itself are treated as normal (e.g. bad login), not session expiry.
- `hooks/useAuth.ts` owns login/logout/role-switch. Role switching does a **hard navigation** (`window.location.assign`), not a client-side redirect — the backend revokes the old session as part of the switch, so a full page teardown avoids racing in-flight requests against the auto-logout handler.
- Multi-role accounts pick a role via `/auth/select-role` after login when the backend reports `requiresRoleSelection`.

### API layer: generated contract + typed service wrappers + React Query hooks

Three layers, each with a fixed home:

1. **`lib/api/generated/schema.d.ts`** — auto-generated from the backend's OpenAPI spec (`lib/api/generated/openapi.json`, committed). Regenerated by `scripts/typegen.mjs`, verified byte-for-byte by `scripts/check-typegen.mjs` against a live BE checkout. **Never hand-edit** — the header says so. The BE contract is the single source of truth for wire shape (camelCase enforced; typegen throws if the spec isn't `x-be-wire-case: camelCase`).
2. **`lib/api/services/fetch*.ts`** — one file per resource (e.g. `fetchSemesters.ts`), each exporting hand-written request/response interfaces plus a plain object of async functions (`list`, `getById`, `create`, `update`, ...) that call the shared `apiService` (`lib/api/core.ts`, an axios wrapper with `withCredentials: true`, CSRF header injection, and normalized `ApiError` on failure). Endpoints and role restrictions are documented inline as comments above each method.
3. **`hooks/use*.ts`** — React Query hooks per resource (`useSemesters`, `useLecturers`, etc.), each pairing a service function with a query key from `lib/api/adminQueryKeys.ts` / `lib/api/managerQueryKeys.ts`. Mutations invalidate related query keys and show `sonner` toasts on success/error, with domain-specific error branching keyed off `ApiError.code` and `detailCode(error)` (`lib/api/errorDetail.ts`).

When adding a new backend resource: add/extend the `fetch*.ts` service, add query keys to the relevant `*QueryKeys.ts`, then add the `use*.ts` hook — don't call `apiService` directly from components.

### Route structure

`app/` uses **route groups per role** plus a few cross-cutting groups, each with its own `layout.tsx`:

- `(auth)` — `/login`, `/auth/callback`, `/auth/select-role` (no role required)
- `(admin)`, `(manager)`, `(lecturer)`, `(student)` — role-scoped areas, each gated by `proxy.ts`
- `(round-wizard)` — `/manager/rounds/new` and `/manager/rounds/[roundId]` edit flow, isolated into its own group/layout (multi-step round creation)
- `(round-detail)` — `/manager/rounds/[roundId]` detail view, a separate route group from the wizard despite the overlapping path segment

Within a role area, page-local components live in a `components/` subfolder next to the `page.tsx`; cross-page-but-role-scoped helpers live in `_shared/` (e.g. `app/(manager)/manager/_shared/semester-context.tsx`, `manager-shell.tsx`, `labels.ts`).

The Manager area is scoped to a **current semester** via `SemesterProvider` (`app/(manager)/manager/_shared/semester-context.tsx`, wrapping `components/semesters/semester-context.tsx`), persisted to `localStorage` under `manager:lastSemesterId`.

### Shared UI

`components/ui/` is shadcn/ui (`style: base-nova`, neutral base, prefix-less Tailwind, `iconLibrary: lucide` — see `components.json`). Domain components live in top-level folders by resource (`components/committees/`, `components/projects/`, `components/rooms/`, `components/semesters/`, `components/lecturers/`, `components/master-data/`), with `components/shared/` and `components/layout/` for cross-cutting pieces. Path alias `@/*` maps to repo root (see `tsconfig.json`); shadcn aliases in `components.json` mirror this.
